# RustWTM 0.34.0 release scope and validation

## Scope

More process views from Process Explorer and System Informer, and a new
Hardware specifications page. IPC is unchanged at protocol 17
(`crates/wtm-ipc` has no change since 0.33.0), so a 0.33.0 service and a
0.34.0 GUI work together.

- Find handle or DLL: every process with an object open or a DLL loaded
  whose name contains the text, searched one process at a time with the
  Handles view's limits. A search stops at 1,000 hits or after a minute,
  checks its Stop flag between processes, and says how many processes could
  not be opened or not fully named, so "no match" is shown only when every
  process was searched.
- Find Window's Process: a painted crosshair at the end of the Processes
  toolbar. The window under the pointer when it is released names the
  process, which is revealed with the search and filters cleared; released
  over RustWTM it does nothing.
- Windows: a process's top-level windows on this desktop, in Z order with
  visible ones first. Each window must belong to one of the process's
  threads (from a system snapshot, without opening the process), titles and
  classes are read without sending messages, and Switch to restores
  asynchronously and never makes a window topmost. Titles are shown only:
  their `Debug` output and the command log leave them out.
- Memory map: heaps, thread stacks, the PEB and TEBs named, with 32-bit
  copies marked, and heap and stack totals. Stacks and TEBs come from each
  thread's TEB (accepted only when its self pointer matches), the default
  heap from the PEB, other heaps from the signature word in their header.
  This needs the right to read the process's memory; without it the layout
  is still mapped and the panel says the names are missing.
- Inspector graphs: reads and writes, network receive and send, and GPU
  over the same two minutes as CPU and memory, each drawn once used. All
  graphs share one axis width and step in round units.
- Hardware specifications: a banner with the headline figures, then a card
  per part (processor core map and caches, one drawn stick per memory slot,
  drives by capacity, graphics, board and BIOS); every field stays under
  All details. Hybrid processors get no guessed thread dots, and long slot
  names are cut to the stick.
- The Processes toolbar keeps to one row in Turkish and German compact
  windows: Find is an icon, and the search box narrows below 800 points.

The process views read with the GUI's own rights, never through the
service, and the ones that open a process refuse lsass.exe and lsaiso.exe
by the name given and by the image opened.

## Verification

`cargo fmt --check`, `cargo clippy --workspace --all-targets -D warnings`,
`cargo doc` with warnings denied and the 1051 workspace tests pass on the
developer host. Failure paths are tested through seams or small fixtures:
a search limited to the test's own process, a passed deadline that names
no thread, query-only rights that name nothing, a hung-thread window that
is still listed at once, and a guard page at an allocation's base that is
refused by the heap-signature read and stays armed. Nothing exhausts host
resources.

Checked on real hardware, recording counts only:

- Find handle or DLL: a full search took 19 s over 865 processes, 231 of
  which could not be opened without administrator rights.
- Memory map names: 695 processes mapped; 16,539 native stacks named for
  about as many threads; 37 processes refused memory reads and were mapped
  without names; the slowest map took 84 ms. On build 26300 the PEB listed
  1 of a test process's 4 heaps, which is why other heaps are found by
  their header: 3,698 NT heap headers and 244 segment heaps across 653
  readable processes. Named allocations cover about 17% of private
  committed memory, the rest being blocks heaps allocate on their own,
  JIT code and other private memory.
- Windows: 868 windows of 161 of 954 processes, at most 118 for one, the
  slowest list in 41 ms. All 27 windows Windows reported as hung were
  hidden ones (suspended apps), so "Not responding" is shown only on
  visible windows. A test minimizes one of its own windows, and Switch to
  restores it without making it topmost.

The new panels and the spec sheet were rendered in English and Turkish at
wide and compact sizes in both themes and inspected; the release review
renders pass in English, Turkish, German, French and Spanish at 1x and in
Turkish at 1.5x. Hosted Windows CI adds 0.33.0 as an upgrade baseline.

Not verified: Find Window's Process with a real mouse. Its tests drag
with synthetic events and a stand-in for the window lookup; that the
release is seen over another program rests on winit capturing the mouse
on press and egui keeping a drag when the pointer leaves the window, both
read in their sources. Which process a Store app's window reports was not
measured.

Known: `samples_every_physical_disk` failed once when Windows' disk
performance counters returned an error during a parallel run, and passed
on every rerun; it predates this release.

Not provided: process memory contents or strings, 32-bit segment heaps in
the memory map (none was found to verify against), and window lists of
other sessions or desktops.
