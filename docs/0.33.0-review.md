# RustWTM 0.33.0 release scope and validation

## Scope

Four process views from Process Explorer, System Informer and VMMap in the
process inspector. IPC is unchanged at protocol 17 (`crates/wtm-ipc` has no
change since 0.32.0), so a 0.32.0 service and a 0.33.0 GUI work together.

- Security: the token's user SID, session and app container flag, each
  group with how the token uses it (deny only, disabled, integrity, logon
  session, owner, domain-local, mandatory) and each privilege with its state
  and Windows' own localized description. Account names are looked up once
  per SID, off the UI thread.
- Environment: the variables of 64-bit and WOW64 processes, read from their
  process parameters. The block's size comes from the target and is capped
  at 1 MiB. Values are only shown: their `Debug` output is redacted, Hide
  drops them, and they never reach Ask AI, logs or files.
- Handles: type, value, granted access and name from the process's own
  handle list (`ProcessHandleInformation`), refused past 200,000 handles.
  Each handle is copied with no access, its type confirmed on the copy,
  named and closed at once. Only disk files are named, on a helper thread
  with half a second per file; a helper that misses its deadline is left
  behind and no other starts until it returns. At most 5,000 names per read.
- Memory map: allocations from `VirtualQueryEx` with kind, reserved and
  committed size, protection and file; private memory that became
  executable is marked. Only the layout is read; the walk is capped at
  200,000 regions and three seconds and never steps backwards.

Every view reads with the GUI's own rights, never through the service
(which runs as SYSTEM and would show one user another's data), and
re-checks the process's start time. Environment, Handles and Memory map,
which read process memory, copy handles or walk the address space, refuse
lsass.exe and lsaiso.exe by the name given and by the image opened;
Security reads only the token with limited query rights, as Task Manager's
User column does.

## Verification

`cargo fmt --check`, `cargo clippy --workspace --all-targets -D warnings`,
`cargo doc` with warnings denied and the 1021 workspace tests pass on the
developer host. Failure paths are tested through seams: a file namer that
never answers proves the handle reader returns within its deadline, skips
the remaining files and clears its busy flag once the helper finishes; the
memory map's caps are tested with a cap of three regions. Nothing exhausts
host resources: test allocations are kilobytes and freed.

Checked on real hardware, recording counts only:

- Tokens of 695 of 907 processes in 0.94 s, every group named and every
  privilege described.
- Environments of 692 of 929 processes (every one that could be opened) in
  162 ms; a native and a WOW64 child returned an exact value with `=` and
  `;` in it.
- Handles of 684 to 691 processes, every listable one also nameable, the
  slowest in 55 ms; the only incomplete name lists were of processes with
  more than 5,000 handles. A pipe with a synchronous read pending was
  handled in 28 ms and left unnamed.
- Memory maps of 764 processes with limited query rights (728 with full
  ones), the slowest in 88 ms. Summed private committed memory came to
  98.4 to 99.5% of each large process's commit size.

The new panels were rendered in English and Turkish at wide and compact
sizes in both themes and inspected for clipped or untranslated text. Hosted
Windows CI adds 0.32.0 as an upgrade baseline.

Not provided: a system-wide "find handle or DLL" search, process memory
contents or strings, and heap and stack detail in the memory map.
