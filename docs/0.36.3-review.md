# RustWTM 0.36.3 release scope and validation

## Scope

A fix release. IPC is unchanged at protocol 18 (`crates/wtm-ipc` has no
change since 0.36.0), so a 0.36.x service and a 0.36.3 window work
together.

- **Memory map of a starting process.** Naming heaps, stacks, the PEB and
  TEBs read the default heap through the PEB's heap list, which a process
  does not have before its loader runs; the read failed with
  `ERROR_PARTIAL_COPY`, naming stopped and the inspector said the process
  refused to be read. The heap list is now optional: the PEB, TEBs, stacks
  and other heaps are named and the default heap is left out until it
  exists. A process that refuses to be read still fails at the PEB. This
  is what failed CI once for 0.36.2
  (`names_a_32_bit_childs_own_heaps_and_stacks`, reading a 32-bit child
  as it started).
- German writes percentages without a space throughout; 11 catalog
  phrases had "100 %" where the rest have "100%".
- Disks groups a scan's file and folder counts with the narrow space the
  Performance page uses.
- The process inspector's CPU row shows one decimal, as its header and the
  process table do.

## Verification

`cargo fmt --check`, `cargo clippy --workspace --all-targets -D warnings`,
`cargo doc` with warnings denied and the 1170 workspace tests (22
ignored) pass on the developer host; `scripts/ci/verify-release.ps1
-Tag v0.36.3` passes. A new test starts `cmd.exe` suspended, before its
loader runs, and names its memory: it failed with the CI error before the
fix and passes after it. The memory map tests passed eight runs in a row.
CI adds 0.36.2 as an upgrade baseline, with the SHA-256 of its published
MSI (the release asset's digest and its `.sha256` file agree).

Still as they were (see the 0.36.2 review): a compact window's status bar
wraps to a second line and its *More below* marker can cover the last
row; wide tables that scroll sideways cut their last column without an
ellipsis; the singular forms in the Indic and Swahili catalogs were not
checked.
