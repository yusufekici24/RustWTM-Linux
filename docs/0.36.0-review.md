# RustWTM 0.36.0 release scope and validation

## Scope

A feature release. IPC moves to protocol 18 (`crates/wtm-ipc` adds the
request for a device's recorded history), so the GUI, CLI and service are
updated together; the MSI installs all three. A 0.35.0 service and a
0.36.0 window refuse each other during the handshake.

- **Recorded device history.** The service keeps a week of per-minute
  averages and peaks for each disk, network adapter and GPU in
  `history.sqlite`, at most 32 devices (about 22 MB for a full week).
  A device's Performance page shows the last hour, 24 hours or 7 days,
  with unrecorded minutes left empty. Device names are looked up off the
  sample loop, and long histories draw one point per pixel.
- **Containers.** A container's last 24 hours, a minute at a time, kept by
  Docker context and name in `container-history.json` (at most 64
  containers). Container alerts (off by default) notify when a running
  container stays above a CPU or memory limit and when it is back below.
- **Events** lists container alerts and lasting sensor and fan-control
  changes, each with its source, and leads to the process, container or
  sensor it concerns.
- **Support bundle.** About exports one text file for a problem report,
  shown in full before it is saved. Secrets, the account name and profile
  folder are always hidden; process names and paths unless asked for.
  Nothing is uploaded.
- **Overview.** Cards can be hidden and reordered (*Customize Overview…*),
  and the page is redrawn: each resource card shows what its reading is
  made of, the verdict carries the process, thread and handle counts and
  the hottest sensor, and warnings are marked notices. Nothing animates.
- **Updater.** A signed build installs only an MSI signed by its own
  publisher; every release so far is unsigned, so updates still rely on
  the release's SHA-256 until the first signed build is installed. After
  an update the window says what became of it.
- **Fixes.** The service keeps its last 14 daily logs instead of all of
  them; live rate graphs keep their scale for ten seconds after a burst;
  the diagnostic report writes the interface scale as "125%".

## Verification

`cargo fmt --check`, `cargo clippy --workspace --all-targets -D warnings`,
`cargo doc` with warnings denied and the 1166 workspace tests (22 ignored)
pass on the developer host; `scripts/ci/verify-release.ps1 -Tag v0.36.0`
passes. CI adds 0.35.0 as an upgrade baseline, with the SHA-256 of its
published MSI (the release asset's digest and its `.sha256` file agree).

The Overview was rendered in English, Turkish and German, light and dark,
wide and compact, and in a stress state (CPU at 95%, a swarm, a program
not responding, game mode, protection on); `screenshots/overview.png` is
rendered again from it. Its bands are tested for the parts they show and
for a band with no room.

Not visually reviewed for this release: the device history, container
history and alert, support bundle and Events pages beyond their own
kittest and unit tests. The updater's publisher pinning is tested as a policy
over publisher records and on this unsigned test binary; no signed build
exists yet to try it end to end.
